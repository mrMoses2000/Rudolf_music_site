Глава 6: TCP: Соединение

В Linux нет магии "соединения". Есть struct tcp_sock. Когда вы делаете connect(), ядро просто меняет поле sk_state в структуре.

6.1. Конечный автомат: The 3-Way Handshake

СОСТОЯНИЯ ЯДРА (KERNEL STATES)

  1. SYN: Клиент выбирает $Seq = X$. (State: TCP_SYN_SENT).
  2. SYN-ACK: Сервер выбирает $Seq = Y$, подтверждает $Ack = X+1$. (State: TCP_SYN_RECV).
  3. ACK: Клиент подтверждает $Ack = Y+1$. (State: TCP_ESTABLISHED).

6.2. Window Scaling (RFC 1323)

VISUALIZATION: SLIDING WINDOW BUFFER

Стандартный заголовок TCP имеет поле «Window Size» размером всего 16 бит. Это позволяет передать максимум $2^{16} - 1 = 65,535$ байт за раз. В современных гигабитных сетях этого катастрофически мало (труба будет пустой).

Решение: Window Scaling. В SYN пакете стороны договариваются о множителе (Shift Count).

$$TrueWindowSize = WindowField \ll ScaleFactor$$
Например, если Scale = 7, то максимальное окно: $$65535 \times 2^7 = 65535 \times 128 \approx 8.3 \text{ MB}$$

6.3. Congestion Control: CUBIC

Как быстро можно слать данные? Linux использует алгоритм CUBIC. Он описывает кривую роста окна как кубическую функцию от времени $t$:

$$W(t) = C(t - K)^3 + W_{max}$$
  • $W(t)$ — целевой размер окна перегрузки (cwnd).
  • $W_{max}$ — размер окна в момент последней потери пакета.
  • $t$ — время, прошедшее с момента потери.
  • $K$ — время, необходимое для достижения $W_{max}$.

Это уравнение позволяет CUBIC быстро восстанавливать скорость (крутой подъем), аккуратно подходить к пределу (плато), и затем агрессивно искать новую пропускную способность (новый резкий рост).

6.4. Selective Invincibility: SACK (RFC 2018)

Что если из 100 пакетов потерялся только 57-й? Без SACK серверу пришлось бы пересылать всё, начиная с 57-го (Go-Back-N). SACK позволяет сказать: "Я получил всё до 57, а также кусок с 58 по 90".

TCP OPTION: SACK BLOCK LAYOUT

В TCP-заголовке это выглядит как опция (Kind=5).

| Kind=5 (1B) | | Len=10 (1B) | | Left Edge (4B) | | Right Edge (4B) |

Один блок SACK занимает 8 байт (+2 байта заголовка). Поскольку TCP Options ограничены 40 байтами, вы можете передать максимум 4 дырки (блока) за раз.
