Глава 4: Виртуальная Коммутация (Bridge и Veth)

Linux Bridge — это не отдельный процесс. Это модуль ядра, который "ворует" пакеты у физических интерфейсов, используя хук rx_handler.

4.1. Крючок: br_handle_frame

В структуре net_device есть указатель на функцию rx_handler. Когда вы добавляете интерфейс в мост (`brctl addif br0 eth0`), ядро устанавливает этот указатель на функцию br_handle_frame.

4.2. Обучение: Forwarding Database (FDB)

Бридж работает как Ethernet-свитч. Он должен знать, на каком порту находится какой MAC-адрес. Это делается в функции br_fdb_update.

АНАЛИЗ ИСХОДНОГО КОДА ЯДРА: MAC LEARNING

Когда пакет приходит на порт, бридж смотрит на Source MAC:

  1. Берет Source MAC (например, AA:BB:CC:DD:EE:FF) и делает хеш.
  2. Ищет этот хеш в хеш-таблице br->fdb.
  3. Если записи нет — создает новую: "MAC ...FF доступен через порт VethA".
  4. Если запись есть — обновляет timestamp (чтобы она не устарела).
void br_fdb_update(struct net_bridge *br, struct net_bridge_port *source,
                   const unsigned char *addr, u16 vid, unsigned long flags)
{
    /* Calculate Hash of MAC Address */
    struct hlist_head *head = &br->hash[br_mac_hash(addr, vid)];
    struct net_bridge_fdb_entry *fdb;

    /* Look for existing entry */
    fdb = fdb_find(head, addr, vid);
    
    if (likely(fdb)) {
        /* Update timestamp - device is alive */
        fdb->updated = jiffies;
    } else {
        /* Create NEW entry (Learning) */
        fdb = fdb_create(head, source, addr, vid, flags);
    }
}

4.3. Решение: Flood или Forward

Далее бридж смотрит на Destination MAC:

  • Если MAC есть в FDB (и он на другом порту) -> Forward (отправить только туда).
  • Если MAC нет в FDB (неизвестен) -> Flood (отправить на ВСЕ порты, кроме входящего).
  • Если MAC - Broadcast (FF:FF:FF:FF:FF:FF) -> Flood.
