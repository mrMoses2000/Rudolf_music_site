Глава 3: Namespaces и Контейнеры

В исходном коде ядра Linux нет ни одной структуры, названной "Container". Docker — это просто удобная обертка над двумя механизмами: Namespaces (Namespace Isolation) и Cgroups (Resource Control).

3.1. Взгляд со стороны ядра: task_struct

Каждый процесс в ядре представлен структурой task_struct. В ней есть поле nsproxy: 

struct task_struct {
    ...
    /* Namespaces */
    struct nsproxy *nsproxy;
    ...
};

struct nsproxy {
    atomic_t count;
    struct uts_namespace *uts_ns;
    struct ipc_namespace *ipc_ns;
    struct mnt_namespace *mnt_ns;
    struct pid_namespace *pid_ns_for_children;
    struct net           *net_ns; /* THIS IS THE KEY */
};

Когда вы делаете ip link add, ядро не добавляет интерфейс в какой-то глобальный список. Оно берет указатель current->nsproxy->net_ns и добавляет устройство в список, привязанный именно к этому namespace.

ТРАССИРОВКА СИСТЕМНОГО ВЫЗОВА: CLONE_NEWNET

Когда демон Docker запускает контейнер, он вызывает системный вызов clone() (или unshare()) с флагом CLONE_NEWNET.

  1. Ядро видит флаг CLONE_NEWNET.
  2. Оно выделяет новую структуру struct net в памяти ядра (отдельную от init_net).
  3. В этой новой структуре создается свой пустой список сетевых интерфейсов, своя таблица маршрутизации (FIB) и свои правила iptables.
  4. В новой структуре автоматически создается только lo (loopback) интерфейс.
  5. Поле nsproxy->net_ns нового процесса начинает указывать на эту новую структуру.

Результат: Процесс физически не может "увидеть" eth0 хоста, потому что в его "вселенной" (struct net) этого указателя просто не существует.
