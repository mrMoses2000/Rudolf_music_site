Глава 5: Рекурсивный DNS Резолвер

Прежде чем отправить первый TCP SYN пакет, приложение должно узнать IP-адрес. Это задача DNS Resolver. В Linux это не магия ядра, это обычная библиотека (glibc), работающая в User Space.

5.1. Системный Вызов: getaddrinfo

Когда ваш код вызывает getaddrinfo("google.com", ...), происходят следующие события:

  1. Config Parsing: Glibc (функция __libc_res_nquery) читает /etc/resolv.conf для получения списка nameservers.
  2. Kernel Transition: Создается UDP сокет через socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP).
  3. Packet Assembly: Библиотека формирует буфер байтов. В файле resolv/res_send.c это функция __res_context_send.

НУКЛЕОЛЯРНЫЙ УРОВЕНЬ: ЗАГОЛОВОК DNS

Это не просто "заголовок". Это битовая карта. В C это выглядит как struct dns_header: 

struct dns_header {
    uint16_t id;      // 16 бит: Случайный ID (напр. 0x1A2B) для связи с ответом
    
    // Флаги (всего 16 бит) - Разберем по частям:
    uint16_t qr : 1;  // Запрос (0) или Ответ (1)
    uint16_t opcode:4;// 0=Стандарт, 4=Notify
    uint16_t aa : 1;  // Authoritative Answer (Это ответ от "главного" сервера?)
    uint16_t tc : 1;  // Truncated (Пакет > 512 байт? Иди в TCP)
    uint16_t rd : 1;  // Recursion Desired (Клиент: "Сделай все сам, плз")
    uint16_t ra : 1;  // Recursion Available (Сервер: "Могу копать")
    uint16_t z  : 3;  // Reserved (Нули)
    uint16_t rcode:4; // Return Code (0=ОК, 3=NXDOMAIN - Нет такого домена)
    
    uint16_t q_count; // Кол-во вопросов
    uint16_t ans_count; // Кол-во ответов (Resource Records)
    uint16_t auth_count;// Кол-во Authority RRs
    uint16_t add_count; // Кол-во Additional RRs
};

Бит RD (Recursion Desired) — самый важный для клиента. Если его не выставить (0), сервер ответит ссылкой на другой сервер, и клиенту придется делать работу самому. Glibc всегда ставит RD=1.

2. Question Section (Wire Format)

Имя google.com кодируется как последовательность Label-ов с префиксом длины (Pascal String concept): 

[0x06] 'g' 'o' 'o' 'g' 'l' 'e'   (Length 6)
[0x03] 'c' 'o' 'm'               (Length 3)
[0x00]                           (Null Terminator = Root)

Это позволяет парсить имя без сканирования на наличие точек.

5.2. Логика UDP vs TCP

Glibc отправляет пакет через sendto(). Если в ответ придет пакет с флагом TC=1 (Truncated), библиотека тут же закроет UDP сокет, откроет TCP (порт 53) и повторит запрос внутри потока. Это происходит при больших размерах ключей DNSSEC.

Если локальный резолвер не знает ответа, он начинает рекурсию:

  1. Спрашивает Root Server (один из 13 мировых IP, например 198.41.0.4). "Кто отвечает за .com?"
  2. Root отвечает: "Я не знаю IP гугла, но знаю, что за .com отвечают сервера Verisign".
  3. Резолвер спрашивает сервер Verisign. Тот посылает на ns1.google.com.
  4. Наконец, ns1.google.com отдает заветный IP.
