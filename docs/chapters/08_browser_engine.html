Глава 8: Браузерный движок

Браузер — это операционная система внутри операционной системы. V8 — это не интерпретатор JIT-компилятор.

8.1. Критический Путь Рендеринга (Critical Rendering Path)

Что происходит, когда вы получаете HTML байты?

graph TD HTML[HTML Bytes] --> Token[Tokenizer] Token --> DOM[DOM Tree] CSS[CSS Bytes] --> CSSOM[CSSOM Tree] DOM --> RenderTree[Render Tree] CSSOM --> RenderTree RenderTree --> Layout[Layout (Geometry)] Layout --> Paint[Paint (Pixels)] Paint --> Composite[Composite (Layers)]
  • DOM: Содержит все теги (даже display: none).
  • Render Tree: Содержит только ВИДИМЫЕ элементы. head и display: none удаляются.
  • Layout (Reflow): Браузер вычисляет x, y, width, height для каждого прямоугольника. Самая дорогая операция.

УБИЙЦА ПРОИЗВОДИТЕЛЬНОСТИ: СИНХРОННЫЙ REFLOW

JavaScript меняет стили лениво. Но если вы прочитаете геометрическое свойство сразу после записи, вы заставите браузер бросить всё и пересчитать Layout. 

// WRITE
div.style.width = '100px';

// READ (Danger!)
// Browser MUST calculate Layout NOW to give you the answer.
console.log(div.offsetWidth); 

// WRITE AGAIN
div.style.height = '100px';

8.2. Event Loop: Микрозадачи и Макрозадачи

VISUALIZATION: CALL STACK & QUEUES

JavaScript однопоточен. Каков приоритет задач?

  1. Call Stack: Синхронный код (console.log). Выполняется до пустоты.
  2. Microtasks (VIP): Promise.then, MutationObserver. Выполняются ВСЕ сразу, как только стек пуст. Если они добавляют новые микрозадачи — браузер зависнет.
  3. Render Step: Раз в 16мс (60 FPS) браузер обновляет кадр (Style, Layout, Paint). requestAnimationFrame.
  4. Macrotasks (Plebs): setTimeout, I/O. Выполняется ТОЛЬКО ОДНА за раз, после рендера.
